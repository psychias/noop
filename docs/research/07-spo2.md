# 07 – SpO₂ from red/infrared PPG

Written 2026-11-10 on branch `research/metrics-literature` from the tree at `2a1de760`. Phase 1 of
`RESEARCH_BRIEF.md`; reads `docs/research/00-inventory.md` §2.7 as its starting point. Every source
in §7 was fetched this session (DOI / PMID / URL recorded); anything that could not be fetched is in
§8 and nothing below rests on it. Wording is deliberately non-medical: NOOP's numbers are
approximations and this document does not change that.

**Verdict in one line:** computing a blood-oxygen percentage from the WHOOP 5.0 optical records NOOP
holds today is **not feasible**, and no amount of metrics-layer work changes that; the only honest
sources of an SpO₂ figure remain an import (Apple Health / Health Connect / CSV) and, *if* it is ever
confirmed across devices, a strap-computed field. Details and evidence follow.

## 2. Recommended method(s) from the literature

### 2.1 How a pulse oximeter actually produces a percentage

- **Ratio of ratios.** Nitzan, Romem & Koppel 2014 [S1] define `R = (AC/DC)₁ / (AC/DC)₂` for two
  wavelengths, "generally red and infrared", and give the calibration only in the general form
  `SaO₂ = (k₁ − k₂R)/(k₃ − k₄R)` with constants "fitted to calibration data". Mannheimer 2007 [S2]
  explains why the Lambert–Beer derivation is only a starting point: tissue scattering breaks the
  simplifications and "manufacturer calibration usually accounts for it", which is why the curve is
  **empirical, per sensor design and per site**, not a universal formula. The TI reference design
  [S16] shows the same thing from the engineering side: an "Empirical and Theoretical R to SaO₂"
  figure that diverge, with a linear fit "safely assumed" only because "Oxygen Saturation seldom drops
  below 80 %". (The often-quoted `SpO₂ ≈ 110 − 25R` appears in none of the sources fetched this
  session; see §8.)
- **Calibration is a human desaturation study, not a fit on one wearer's nights.** Nitzan 2014 [S1]:
  R is "measured in several healthy volunteers alongside co-oximetry of extracted arterial blood, with
  several SaO₂ values per person"; the authors note that ethical restrictions keep manufacturers from
  reducing SaO₂ below ~80 % during calibration and that error grows below 70–80 %. The regulatory
  version is stricter. FDA 2013 guidance [S3] recommends the ISO 80601-2-61:2011 Annex EE.2 study "on
  10 or more healthy subjects that vary in age and sex", "200 or more data points (paired observations:
  pulse oximeter, co-oximeter)" distributed over **70–100 %**, "at least 2 darkly pigmented subjects
  or 15 % of your subject pool, whichever is larger", reported as Bland–Altman with multiple
  observations per individual, and an **Arms** (root-mean-square difference SpO₂ − SaO₂) of
  **≤ 3.0 % transmittance (wrap/clip), ≤ 3.5 % ear clip, ≤ 3.5 % reflectance**. A practitioner
  description of the protocol [S7]: 10–12 stable plateaus at roughly 70, 73, 76, 80, 83, 86, 89, 92,
  95, 98 and 100 %, arterial samples drawn after 30–60 s of stability through a radial catheter and
  run on a multi-wavelength co-oximeter (ABL-90 / OSM3 class). The January 2025 FDA draft [S4]
  tightens all sensor types to **Arms < 3 % with the 95 % CI upper limit < 3 %**, adds co-primary
  bias analyses by Monk Skin Tone (MST) group and by Individual Typology Angle (ITA) at the sensor
  site, and sets non-disparity criteria (largest MST-group bias difference < 3.5 % for
  70 ≤ SaO₂ ≤ 85 %, < 1.5 % above 85 %). ISO 80601-2-61 itself moved from edition 2 (2017) [S5] to a
  2026 edition; a secondary summary [S6] reports the Arms limit falling from ≤ 4.0 % to ≤ 3.0 %, the
  minimum subject count rising from 10 to 24, and mandatory ITA + MST pigmentation categorisation.
- **Accuracy that calibrated, cleared devices actually reach.** Nitzan 2014 [S1]: manufacturers claim
  2 % (as an SD, in healthy subjects); clinical studies find 3–4 % for a single reading and 2–3 % when
  following one patient. Everything a hobby calibration could hope for sits *above* that floor.

### 2.2 Transmission fingertip vs reflectance wrist

Transmission oximetry is confined to fingertips and earlobes; reflectance can be applied "on any
accessible site", with the forehead the main validated reflectance site and comparative studies
conflicting [S1]. The wrist is the hard case: reflectance there has "a significantly lower
signal-to-noise ratio compared to the standard transmission method", wrist perfusion is much lower
than finger perfusion and the site is more motion-prone [S12]; "the performance of the reflectance
pulse oximeter depends on the exact placement of the sensor" [S13]. Results for wrist devices that
*do* have known wavelengths, kHz multiplexing (§2.3) and a factory desaturation calibration:

| Study (device, reference) | n / pairs | Range | Bias | 95 % LoA | Arms / RMSE |
|---|---|---|---|---|---|
| Kirszenblat & Edouard 2021 [S10] — Withings ScanWatch vs ABL90 co-oximetry (controlled desaturation, 70–100 %, Withings-funded) | 14 / 275 right, 244 left (of 322 samples) | 70–100 % | +0.98 % right, +1.56 % left | −4.66…+6.62 % right; −3.46…+6.58 % left | RMSE 3.00 % / 2.97 % |
| Gerboni et al. 2023 [S11] — Empatica EmbracePlus vs multi-wavelength co-oximetry (70–100 %, ~30 % Fitzpatrick V–VI; manufacturer study) | 15 / 373 | 70–100 % | +0.05 % | −4.7…+4.8 % | Arms 2.4 % (2.2 % dark, 2.5 % light) |
| Walzel et al. 2023 [S12] — Apple Watch 8 / Samsung Galaxy Watch 5 / Withings ScanWatch vs Masimo Radical-7 **finger oximeter** (10–14 % O₂ breathing, healthy young Caucasian volunteers) | 18 / 274, 283, 238 | full | −0.1 / −2.6 / +0.4 % | −4.4…+4.2 / −8.1…+2.9 / −6.5…+7.2 % | Arms 2.2 / 3.8 / 3.5 %; failed readings 5 % / 2 % / 17 % |
| Rafl et al. 2022 [S13] — Apple Watch 6 vs Masimo Radical-7 (12 % O₂, healthy) | 24 / 642 | full; < 90 % | 0.0 %; +1.2 % | −5.8…+5.9 %; −5.3…+7.6 % | Arms 3.0 %; 3.4 % below 90 % |
| Pipek et al. 2021 [S14] — Apple Watch 6 vs two fingertip oximeters, COPD/ILD/healthy | 100 subjects | clinic | +0.8 % | −2.7…+4.1 % | r 0.81, ICC 0.90 |
| Spaccarotella et al. 2022 [S15] — Apple Watch 6 vs standard pulse oximeter, lung/cardiac disease + controls | 265 screened | clinic | −0.23 % (SD 1.66) | −3.49…+3.04 % | r 0.89 |
| Hermand et al. 2021 [S9] — Garmin Forerunner 245 vs medical oximeter, normoxia + simulated 3000–5500 m | 10 | down to ~70 s % | reads high (P < 0.001) | — | > 50 % of readings outside ±3 %, > 80 % above 4800 m |

Reading across the table: even best-in-class wrist reflectance with full manufacturer knowledge
sits at Arms ≈ 2.2–3.8 % with individual-night limits of agreement of roughly ±4–7 points, up to
17 % failed readings, averaging windows of 8–30 s per reading (Withings ~30 s, Apple 15 s, Samsung
12–17 s [S12]), and at least one shipped product that fails outright under real desaturation [S9].
Note that four of the seven rows compare a watch with another *pulse oximeter*, which measures
agreement between two estimates rather than accuracy against arterial blood.

### 2.3 Skin pigmentation

Sjoding et al. 2020 [S8] paired SpO₂ with arterial SaO₂ in two cohorts (10,789 pairs from 1,333 White
and 276 Black inpatients at Michigan; 37,308 pairs from 7,342 White and 1,050 Black patients
multicentre) and found occult hypoxaemia (SaO₂ < 88 % while SpO₂ read 92–96 %) in 11.7 % of Black vs
3.6 % of White patients in the Michigan cohort (11.4 % vs 3.6 % adjusted). Fawzy et al. 2022 [S17]
(1,216 COVID-19 patients, 32,282 pairs) found SpO₂ overestimating SaO₂ by about 1.7 % (Asian), 1.2 %
(Black) and 1.1 % (non-Black Hispanic) relative to White patients, with occult hypoxaemia in
28.5–30.2 % vs 17.2 %. Cabanas et al. 2022 [S18] (41 studies) summarise a positive bias in darkly
pigmented skin "particularly under low saturation conditions", graded low-certainty. This is why the
2025 FDA draft and the 2026 ISO edition make pigmentation-stratified bias a co-primary endpoint. For
NOOP it means a calibration fitted on one wearer, even if it existed, would not be transferable.

### 2.4 Time-multiplexed red/IR sampling: what "multiplexed" means commercially

Commercial oximeters **never** sample red and IR simultaneously either; they alternate the LEDs fast
enough that the two samples are effectively coincident with respect to the pulse:

- TI's MSP430 reference oximeter [S16]: "The two LEDs are time multiplexed at 500 times per second";
  the photodiode output is sampled at 1000 sps alternating IR/red, "therefore each LED signal is
  sampled at 500 sps"; the two wavelengths are 660 nm and 940 nm; a DC-tracking IIR filter recovers the
  AC term and ambient 50/60 Hz noise is filtered out.
- TI AFE4400 pulse-oximeter front end [S19]: pulse repetition frequency **62.5–5000 SPS**, and within
  every period a fixed four-phase sequence "convert LED2 → LED2 ambient → LED1 → LED1 ambient", so
  each wavelength carries its own ambient-light sample for subtraction and the red–IR separation is a
  fraction of one period (≤ 16 ms at the slowest setting, sub-millisecond at typical ones).

So the question for NOOP is not "multiplexed vs simultaneous" but **what interleave period, with
what metadata**. At a cardiac period of 0.6–1.2 s and a systolic upstroke of ~0.1–0.3 s, a red–IR
offset of a few milliseconds is negligible and sub-sample interpolation is unnecessary; an offset of a
full second or more (channels captured in *different* records or different bursts) puts the two AC
amplitudes on different beats and different respiratory/baseline phases, and R is no longer a
property of one pulse. Separate 25-sample bursts per block in R20 (§4) are the latter case unless
the strap's intra-second phase is known, which it is not. A 24–25 Hz per-channel rate is itself
adequate for the pulse AC amplitude (fundamental 0.5–3 Hz) — sampling rate is **not** the blocker.
The blockers are listed in §3.

### 2.5 What the metrics layer can legitimately do

Given §2.1–2.4, the literature-backed recommendation for an offline companion app is:

1. **Do not compute SpO₂ from an uncalibrated sensor.** A number without a desaturation
   calibration has no Arms, and the accuracy standard is a property of the *device + algorithm +
   calibration* bundle, not of the formula.
2. **Accept SpO₂ only from a calibrated source**: an imported value (fingertip oximeter app, Apple
   Health, Health Connect, the official CSV export) or — if ever confirmed — a value the strap itself
   computed with the manufacturer's calibration.
3. **Report nightly summaries, not single readings**, and keep them descriptive: nightly mean and
   a low percentile with the sample count, no "events", no thresholds, consistent with `docs/SCOPE.md`.

## 3. Gap analysis

**NOOP's implementation is already the recommended one: it refuses.** The gap is therefore not
"NOOP vs the method" but "what would have to be true for the method to apply", listed so future
contributors can check each item instead of re-arguing it.

| Requirement of the ratio-of-ratios method | WHOOP 5.0 as NOOP decodes it | Status |
|---|---|---|
| Two channels of **known** wavelength (one red ~660 nm, one IR ~900–940 nm) | R20 slots are "A/B, not red/infrared/green"; source/emitter selectors are unresolved enums; R18 @106–109 pairs "do not independently identify two wavelengths"; R26 "does not identify simultaneous red and infrared channels" (`docs/PROTOCOL_SENSORS.md`) | **Missing — fatal.** Without identity, even the *sign* of the R→SpO₂ slope is unknown; the only way to learn it is to correlate R against a reference across a real desaturation, which the owner cannot ethically produce. |
| Red and IR samples from the **same pulse** (ms-scale interleave, §2.4) | Channels live in separate 25-sample R20 blocks / R26 bursts; intra-second phase, burst alignment and whether the five blocks are even acquired in the same second are unresolved | **Unknown; likely violated.** |
| A true **DC** term per channel (AC/DC normalisation is what cancels LED drive and detector gain) | R20 headers carry per-slot "Offset A/B" (multiples of 800 in unresolved units) and "Range A/B"; R26 stores a base value plus clipped deltas | **Compromised.** If an unknown offset was subtracted before digitisation, the stored DC is wrong by an unknown amount and R is wrong by an unknown factor. Recoverable only after the header units are established (protocol work, out of scope here). |
| Per-channel **ambient** subtraction | A zero-drive fourth block "has served as a dark control; that pattern is not a guarantee under every routing configuration" | Partial, unverified. |
| **Calibration curve** fitted on ≥ 10 subjects, ≥ 200 co-oximetry pairs over 70–100 % [S3], pigmentation-stratified [S4][S6] | None; WHOOP's own curve is proprietary and unknown; the owner's nights span ~94–99 % | **Missing — fatal.** A 2-parameter fit over a 5-point range cannot be validated, and a fit on one wearer does not transfer (§2.3). |
| Signal-quality gates and an 8–30 s averaging window | `PpgHr` has an autocorrelation confidence for HR only | Would need building; moot given the rows above. |

**Expected accuracy impact of attempting it anyway: negative, high.** Calibrated wrist devices with
all of the above satisfied reach Arms 2.2–3.8 % with ±4–7 point limits of agreement (§2.2). Each
missing row above adds an unknown systematic error that no on-device test can detect, and the
output would land in Apple Health as a percentage indistinguishable from a real one. That is the
#194 trap with higher stakes, and `AGENTS.md` forbids it: "never make it the default or feed it a
downstream gate (recovery, illness) on thin evidence".

**Byte-82 is a different question.** If @82 is a strap-computed percentage, WHOOP's pipeline has
already done the calibration; NOOP would only be *reading* a number, not deriving one. The current
state of that evidence: one 8-night series tracks the app (corr +0.99) and two nights on another
device move the opposite way (`Interpreter.swift`); the firmware string `generated a valid SPO2
during sleep` proves the strap *has* such a pipeline but carries no value; the byte is duty-cycled
and phase-locked (`validate_spo2_candidate.py`), which is one plausible explanation for a capture
that reads "opposite" when it is mis-aligned, but that is a hypothesis for the tool to test, not a
finding. No published accuracy figure for WHOOP's own SpO₂ against arterial blood was found this
session (§8). The gap to close is **multi-device evidence**, which is protocol/field work and stays
outside this brief.

## 4. WHOOP 5.0 input constraints

**What the 5.0 gives NOOP (all from `docs/PROTOCOL_SENSORS.md` and the inventory):**

- **R18 (124 B, per second):** `@82` raw byte (sleep-adjacent, 0x80/0xA0 sentinels, nonzero only
  while asleep, duty-cycled); `@106/@107` "optical baseline-like" and `@108/@109` "optical
  amplitude-like" byte pairs (byte-reversed halfwords; simultaneous 128 is a quality sentinel, 0 is
  off-wrist). The two pairs look like the strap's own AC/DC bookkeeping for two optical channels —
  exactly the shape a ratio-of-ratios needs — but with u8 resolution, no wavelength label, no unit,
  and a firmware-chosen scale. They are carried raw by design.
- **R20 (2,140 B):** five measurement blocks, each a 21-byte header (sample count 0–50, emitter
  selectors A/B, drive A/B, detector routing A/B, range A/B, offset A/B) and two 200-byte i32 slots.
  The corpus always shows counts `[25, 0, 0, 25, 25]`: three active blocks × two slots × 25 samples —
  nominally 25 Hz per slot if the record spans one second. Block 3 has a fallback source; a zero-drive
  block has acted as a dark control.
- **R26 (88 B):** one optical channel as a base value + 24 clipped i16 deltas (25 samples, one-second
  interpretation), with a motion summary float and acceptance byte. `PpgHr` already consumes this
  24 Hz stream for HR continuity only; "PPG carries NO body motion… NOT HRV" (`PpgHr.swift`).
- **No** `spo2Sample(red, ir)` on 5.0 — that table is the 4.0 v24 layout; `spo2Pct` is nil.

**What is missing or unresolved, in order of how fatal it is for SpO₂:** wavelength identity of any
channel → whether two active blocks are the same pulse → the unit of the header offsets/ranges (so a
true DC could be reconstructed) → whether the dark block is a usable ambient reference → a calibration
curve → any reference below ~94 % to validate against.

**Fallback / graceful degradation recommendation (what the metrics layer should do now):**

1. Keep `spo2Pct = nil` for WHOOP 5.0 and keep the `spo2` capability token stripped (v36). An absent
   tile is the correct readout; a fabricated one is the failure mode the repo rules name.
2. Keep the instrumentation that exists (`auxByte82` storage, `nightlySpo2CandidateMean`,
   `Spo2ReTrace`, the optical-experiment harness) exactly as it is: raw, gated to Test Centre,
   never scored. Do not add an "R from R20" readout to the metrics layer; a ratio of two unlabelled
   columns is not instrumentation of anything, because there is no artefact to validate it against.
3. Let imports fill the slot. The HealthKit / Health Connect readers and the CSV importer already
   deliver a calibrated `spo2Pct`; `RecoveryScorer` folds it only when present. That path is the
   supported one and should stay the only one that writes a percentage.
4. If @82 is ever promoted (protocol decision, not this brief's): the metrics layer's job is
   `nightlySpo2CandidateMean` grown into a nightly summary — see §6 — with the capability token
   restored only on straps where the field is observed, so the tile cannot look broken on a strap
   classified `feature_absent`.

### 5.2 Metrics to report (if anything is ever evaluated)

Per ISO 80601-2-61 / FDA [S3][S4][S7]: **Arms** = √(mean((SpO₂ − SaO₂)²)) over the pooled pairs,
with a 2-sided 95 % CI; Bland–Altman for **multiple observations per individual** (bias, within- and
between-subject variance, 95 % limits of agreement — the FDA cites Bland & Altman 2007 for this);
error plots of (SpO₂ − SaO₂) vs SaO₂ per subject and pooled; failed-reading proportion; and, where a
population is involved, bias stratified by pigmentation (MST / ITA). For a consumer-vs-consumer
comparison the honest label is *agreement*, not accuracy (§2.2).

### 5.3 Owner validation with a fingertip oximeter

This plan applies to a **confirmed strap-computed field** (byte 82 after promotion) or to imported
values. It does **not** apply to a NOOP-computed SpO₂, because §3 shows there is nothing to validate.

- **Reference.** A transmission fingertip oximeter that states its own Arms (cleared devices
  typically label ≤ 2–3 % over 70–100 % [S1][S3]); ideally one that logs per-second or per-minute SpO₂
  overnight, so the nightly time course and not just a morning spot check can be compared. Record the
  model and its labelled accuracy with the results (`docs/VALIDATION_PROTOCOL.md` R7).
- **Design.** ≥ 20–30 nights on the same wrist/finger pairing, pre-registered (R1): primary endpoint
  = agreement between NOOP's nightly mean (from the strap field) and the oximeter's nightly mean over
  the same in-bed window; secondary = nightly 5th percentile. Report bias, SD, 95 % LoA and Arms with
  n; plot error vs reference. Keep every night, including ones the oximeter dropped (report the drop
  rate).
- **What it can and cannot show.** A healthy sleeper's nights span roughly 94–99 %, so the study can
  only establish agreement **in the normal range**; it cannot say anything about readings below
  ~90 %, and the write-up must say so (R8 "cannot be measured" is a result). Breath-holds or any
  attempt to induce desaturation are out of the question (the optical-experiment doc already says
  "Do not hold your breath or attempt desaturation").
- **Acceptance for the metrics layer.** Agreement alone does not promote the field; promotion is a
  cross-device protocol decision (#103). The owner's series would be *one* device's evidence for that
  tool, posted as aggregate statistics only (`validate_spo2_candidate.py --postable`), never raw
  values.

## 6. Implementation sketch

**For deriving SpO₂ from PPG: not applicable — infeasible** (§3). No Swift/Kotlin work is proposed,
and no instrumentation computing a ratio from R20/R26 columns is proposed either, because an
unlabelled ratio has no artefact to be validated against and would only invite the #194 mistake.

**What we recommend instead (small, safe, S effort):**

1. *Keep nil.* Leave `spo2Pct = nil`, the v36 capability strip and the guard test
   `testHistoricalV18OpticalFieldsAreNotNamedPhysiologically` untouched. Consider a one-line doc
   note in `docs/ANALYTICS.md` pointing here, so the next contributor finds the reasoning without
   re-deriving it.
2. *Allow import, and only import.* The HealthKit / Health Connect / CSV paths remain the sole
   writers of a percentage. If the owner uses a fingertip oximeter that syncs to Apple Health, NOOP
   already reads it; no change needed.
3. *No fabricated %.* Nothing in the Health, Readiness or Insights screens should render a blood
   oxygen figure for a WHOOP 5.0 unless it came from (2).

**Only if @82 is promoted upstream** (outside this brief), the metrics-layer twin on both platforms
would be a nightly summary, byte-identical across Swift and Kotlin and oracle-tested per `AGENTS.md`:

```text
nightlySpo2Summary(sessions, aux) -> (mean, p05, samples)?
  keep a in aux where 70 <= a.auxByte82 <= 100           // sentinels (bit 7) and codes (<70) dropped
                 and some session has start <= a.ts <= end
  group kept samples by the strap's duty-cycle window     // one value per window, not per second,
                                                          // mirroring validate_spo2_candidate.py
  require windows >= minWindows (e.g. the equivalent of >= 30 min of in-bed coverage)
  mean = round(mean(window means)); p05 = 5th percentile of window means
  return (mean, p05, windows)                             // samples travels with the value, always
```

Then: write `dailyMetric.spo2Pct` from it **only** behind a per-strap capability that is set when
the field has been observed on that strap, restore the `spo2` token through a new additive migration
(never by editing v36), export via the existing HealthKit/Health Connect writers, and leave
`RecoveryScorer`'s SpO₂ weight exactly where it is for imports. Risk: medium — the value's accuracy
is WHOOP's, unknown and unpublished (§8), so the UI copy must keep calling it approximate.
